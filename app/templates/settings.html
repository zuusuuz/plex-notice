Plex connection

Where this app reaches your Plex server: http:// + your server's LAN IP + :32400, e.g. http://192.168.1.10:32400. No trailing slash.

IP address or container name?

IP address (recommended): e.g. http://192.168.1.10:32400, the LAN IP of the machine running Plex and Plex's port. Works from any Docker network, as long as Plex publishes port 32400 on the host (or runs with network_mode: host), and also works if Plex isn't in Docker at all.

Container name: http://plex:32400. Only works when this app's container and the Plex container share a Docker network (both list the same network under networks: in compose). Use the Plex service's container_name. Traffic then stays inside Docker and survives a host IP change.

Avoid a public address like https://plex.example.com here: local is faster and doesn't depend on DNS or a reverse proxy.

Lets the app act as you (the server owner) in Plex. Stored in plain text in /data/settings.json, so keep that folder private. Leave blank to keep the saved one.

How do I find my token?
  1. Open Plex Web and sign in as the server owner.
  2. Open any movie → ⋮ (More) → Get Info → View XML.
  3. A new tab opens. In its address bar, copy everything after X-Plex-Token= (up to the end, or the next &).
The token stays valid until you sign out of all devices or change your Plex password. Also in Guide → Plex setup.

Only matters if the Plex URL starts with https://. Untick it if Plex uses its own self-signed certificate, or simply use http:// on your LAN.

Notice behaviour

The fake "date added" that keeps the notice at the front of Recently Added (Plex sorts that row newest-first, so a date in the future always wins). Default 2037-01-01.

Why not 2099?
Dates after 19 January 2038 don't fit in the 32-bit timestamps some software still uses. A client like that could read 2099 as a date in 1900-something and push the notice to the bottom. Anything in 2037 is safe.

Gives the notice the same future date as its release date, so it also leads the "Recently Released Movies" row, which is sorted by release date rather than date added.

Gives the notice a hidden sort title starting with !, so it's also first when someone browses the Movies library alphabetically. The visible title is unchanged.

How often the app checks the live notice is still pinned and titled correctly in Plex, and fixes it if not (e.g. after someone hits "Refresh metadata"). 0 turns the check off. Default 10. Scheduled auto-removal runs every 30 seconds regardless of this setting.

How long to wait for Plex to pick up the clip after activation before giving up and rolling back. Only the notice folder is scanned, so it's usually under 10 seconds. Raise it if your mergerfs disks spin down and take a while to wake. Default 120.

Leave this off unless you understand it. The normal, safe way to remove a notice is Plex's own delete, which needs Allow media deletion turned on in Plex (Settings → Library).

Why is this risky with mergerfs?
"Empty trash" removes every unavailable item in the whole Movies library, not just the notice. If a disk in your mergerfs pool is offline or slow to mount, its movies show as unavailable, and emptying the trash would delete their Plex entries. When the disk returns they'd be re-added as brand-new, flooding Recently Added and losing their custom posters and edits. With this off, a notice Plex won't delete is just hidden (dated 2000) and retried later.
Cloudflare status page optional

Sends messages to the Cloudflare Worker that shows a maintenance page on a site like requests.example.com when your server is unreachable. Needs the Worker, a KV namespace and an API token: set those up first with Guide → Cloudflare status page.

The long ID in your Cloudflare dashboard's address bar, right after dash.cloudflare.com/. See Guide → Account ID.

The ID of the KV namespace your Worker reads (e.g. plex-notices): open it in Cloudflare → Metrics tab → Namespace ID box on the right. See Guide → Step 1: KV namespace.

Create one by following Guide → Step 2: API token. Leave blank to keep the saved one.

When a notice is activated without an auto-remove time, its planned status message expires after this many hours. With an auto-remove time it expires one hour after that time instead. Either way it's also cleared when you remove the notice. Default 24.

What the status page says when the server is down and no planned message is active. It's sent to Cloudflare automatically when you save settings with Cloudflare enabled and this text changed. Use Send default to Cloudflare to send it again at any time (it uses what's typed, even before saving).

Optional. Without a password, anyone who can reach this page can post notices to your Plex users, so keep it LAN/VPN-only: a reverse-proxy address such as notices.example.com restricted to your LAN, or just http://<server-ip>:{{ port }}. Turn this on if anyone else on your network shouldn't be able to use it.

Forgot the password?
Add DISABLE_AUTH=true under environment: for this app in your compose file and run docker compose up -d. The app opens without a password; set a new one here, then remove that line and run docker compose up -d again.
