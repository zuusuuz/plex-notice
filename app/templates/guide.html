How it works

About the examples in this guide: replace these placeholders with your own values.
/path/to/movies is your Movies folder on the host · /path/to/compose is the folder holding your compose.yml · 192.168.1.10 is your server's LAN IP · example.com is your domain · /movies is where your Plex container sees your movies.

Plex has no built-in way to message the people you share with. This app fakes one: it adds a short clip to your Movies library dressed up as a notice, with your title, description and a big bold poster, and pins it to the front of Recently Added so it's the first thing everyone sees.

  1. Activate: the app copies your chosen clip into a dedicated folder inside your Movies library (_ServerNotice), asks Plex to scan just that folder, then sets the title, description, poster and background through the Plex API and locks them so Plex doesn't overwrite them.
  2. Pinning: Recently Added is sorted by "date added". The app sets the notice's date to the future (2037 by default), so new downloads always land behind it. No constant re-shuffling is needed. A watchdog re-checks it every few minutes anyway.
  3. Remove: the app deletes the item through Plex and removes the clip, so outside of active notices nothing is left in your library. Each activation creates a brand-new item, so watched ticks never carry over.
  4. Status page (optional): if you use the Cloudflare Worker from this guide, the app also sends a matching message to it, which visitors see on e.g. requests.example.com if the server is offline.

Notices are delivered by Plex, so they're for advance warning (upgrades, electrical work, planned downtime). If Plex is already down, nobody can see them. That's what the Cloudflare status page is for.

Before you start

  • Plex Media Server you own (admin token needed) with a Movies library.
  • Docker with Compose on a machine that can reach Plex over the network and can mount a folder inside your Movies folder.
  • To know which user/group owns your Movies folder: run ls -ln /path/to/movies on the host. The two numbers after the permissions (e.g. 1000 100) are the PUID and PGID this app should use, normally the same as your Radarr and Plex containers.
  • Optional: a reverse proxy (e.g. Nginx Proxy Manager) for a nice address like notices.example.com.
  • Optional: a Cloudflare account with your domain on it, for the status page.

Installing

1. Put the app's files on the server

Copy the plex-notice folder into the folder that holds the compose file running Plex, so you end up with /path/to/compose/plex-notice next to /path/to/compose/compose.yml. It contains the Dockerfile and an app folder. (A separate compose file works too; see the note in step 3.)

2. Folders and permissions

Nothing to do by hand. Docker creates any missing host folders (as root) when the container starts, and the container then hands them to your PUID:PGID before the app runs, the same way LinuxServer images (Radarr, Sonarr…) do it. It only changes the owner of the data folder and of the _ServerNotice folder itself, never anything else in your Movies library.

_ServerNotice is where clips are copied while a notice is active; it's empty the rest of the time. The leading underscore keeps it at the top of folder lists so it's obviously not a real movie. Radarr may list it under Library Import as unrecognised; it won't touch it.

3. Add the service to your compose file

Add this under services: in the compose.yml that runs Plex. Change the four marked lines:

  plex-notice:
    build: ./plex-notice
    image: plex-notice:local
    container_name: plex-notice
    environment:
      - PUID=1000                 # CHANGE: user ID that owns your movies folder
      - PGID=1000                 # CHANGE: group ID that owns your movies folder
      - TZ=Etc/UTC                # CHANGE: your time zone, e.g. Europe/London, America/New_York
      # - MAX_UPLOAD_MB=1024      # biggest clip/image upload allowed
      # - DISABLE_AUTH=true       # only to recover a forgotten password
    volumes:
      - ./plex-notice-data:/data                   # settings, presets, clips, images
      - /path/to/movies/_ServerNotice:/notice      # CHANGE the left half only
    ports:
      - "{{ port }}:{{ port }}"
    # networks:                   # optional: uncomment and use your Plex network's
    #   - plex-network            # name if you want to reach Plex as http://plex:32400
    restart: unless-stopped

Don't add a user: line. PUID/PGID replace it, and a user: line would switch off the automatic permission fixes. The right half of each volume (/data, /notice) must stay as it is. Only the left (host) side changes. Using a separate compose file instead? That's fine, as long as the paths are right. The networks: lines only matter for the container-name option.

4. Build and start it

cd /path/to/compose
docker compose up -d --build plex-notice
docker compose logs -f plex-notice      # Ctrl+C to stop watching

Then open http://192.168.1.10:{{ port }} (your server's IP).

5. Optional: a nice address in Nginx Proxy Manager (or another reverse proxy)

  1. NPM → Hosts → Proxy Hosts → Add Proxy Host.
  2. Details tab: Domain notices.example.com, Scheme http, Forward Hostname/IP 192.168.1.10, Forward Port {{ port }}. Access List: one that only allows your LAN/VPN. Tick Block Common Exploits.
  3. SSL tab: your certificate for that domain, tick Force SSL and HTTP/2 Support.
  4. Save. Uploads of large clips can hit NPM's size limit. If an upload fails with "413", open the host again → Advanced tab and add client_max_body_size 1024m;, then save.

Direct access on http://192.168.1.10:{{ port }} keeps working alongside the proxy address.

Plex setup

1. Allow media deletion (recommended)

Plex Web → Settings (spanner, top right) → under your server, Library → tick Allow media deletion → Save Changes.

This lets the app remove a notice cleanly with Plex's own delete, which only touches the notice item. Without it, a removed notice is hidden from Recently Added (re-dated to 2000) but leaves an "unavailable" entry in the Movies library until you allow deletion and press Retry cleanup on the Dashboard.

2. Connect the app

  1. Get your Plex token: open any movie in Plex Web → ⋮ → Get Info → View XML, and copy everything after X-Plex-Token= in the new tab's address bar.
  2. In this app: Settings → Plex connection. Enter the Plex URL (e.g. http://192.168.1.10:32400) and the token, then press Test connection & load libraries.
  3. Under Plex library & folders, pick your library. Plex will look for notices in shows the path it worked out. With a standard setup there's nothing else to fill in: the notice folder's name is detected from your compose file.
  4. Save, then on the Dashboard press Run checks. Everything should be green (amber is a warning, not a blocker).

Library in a different place

The app works wherever your library lives. The only rule: the folder you mount at /notice must sit directly inside one of the library's folders. The app then works out where Plex will find it:

Plex looks in = the library's folder as Plex sees it + / + the notice folder's name.
The name is detected from your compose line (the last part of the left-hand side), so normally you only pick the library.

Which libraries work?

Movies and Other Videos libraries. TV Shows and Music aren't supported: Plex needs a show/season/episode or artist/album structure there, and Music would need an audio placeholder with square artwork.

Library with several folders

Mount the notice folder inside any one of them, ideally on a disk that's always on. The app asks Plex to check each of the library's folders and uses whichever one has the clip.

Notice folder deeper inside the library

If it's not directly inside a library folder (e.g. /movies/4K/_ServerNotice), open Settings → Advanced: custom Plex path and type the full path Plex sees.

Plex on a different machine

This app writes the clip, and Plex has to read it. Run this app where the files physically live (e.g. on the NAS), or mount the same network share on this app's machine and point /notice at the notice folder on that share. The Plex URL then uses the other machine's IP.

Detection says "couldn't detect"

Some storage setups hide the folder name from the container. Type the name into Settings → Notice folder name, e.g. _ServerNotice.

Why not mount the whole library and pick the folder in the app?

Which host folders a container can touch is decided by Docker when it starts, not by the app inside it. Mounting only the notice folder means the app physically can't write anywhere else, so a bug can never reach your real movies.

Day-to-day use

Media

Upload one or more short clips on the Media page; that's what plays if someone presses Play. A default 5-second clip is included. Upload images there too if you want a photo behind the poster text or your own complete poster.

Presets

A preset is a saved notice: the title and description Plex shows, the poster design, the clip, and an optional status-page message. Make one per kind of event ("Planned maintenance", "Electrical work", "Server upgrade") and duplicate them to tweak dates. The preview shows exactly what Plex will get.

Activating

  1. Dashboard → Activate a notice → pick the preset.
  2. Optionally set Remove automatically at, e.g. when the work should be finished.
  3. If Cloudflare is set up, leave Also set this preset's message ticked so the status page shows your planned message if the server goes down.
  4. Press Activate. The progress list shows each step; it normally takes 10–30 seconds.

The notice is also given the same future release date, so it leads "Recently Released Movies" too (Settings → Also put it first in "Recently Released"). Some apps (especially TV apps) cache their Home screen for a few minutes. If the notice doesn't show straight away, back out to Home or restart the app.

Only one notice at a time

Activating a different preset while one is live replaces it (the old one is removed first). Editing a live preset doesn't change Plex until you activate it again.

Removing

Press Remove notice, or let the auto-remove time do it. If the server was off at that moment, it's removed as soon as the app starts again. Removing also clears the planned status-page message, so the default one applies again.

Watchdog

Every few minutes (Settings → Watchdog check interval) the app checks the live notice still has its pinned date and title, and quietly puts them back if something changed them. Problems show on the Dashboard under Last check.

Before you shut the server down

  1. Activate the notice a day or two ahead so people see it.
  2. Optionally set an auto-remove time for after the work.
  3. Shut down as normal. If you used the status page, it shows the planned message while you're offline.
  4. When everything's back, the notice is removed automatically, or remove it yourself.

Cloudflare status page

Optional, but it covers the gap Plex can't: when your server is off. A Cloudflare Worker sits in front of a website you already expose through Cloudflare (e.g. requests.example.com running Seerr, the request app for Plex and Jellyfin). Visitors pass straight through to your server; if it can't be reached, the Worker shows a maintenance page instead. That page's text comes from Workers KV, which this app writes to.

  • Everything below fits in Cloudflare's free plan.
  • The Worker only reads KV when your server is down, so normal browsing doesn't use KV at all.
  • "Account level" means outside any one domain: click the Cloudflare logo or your account name at the top left.
  • Cloudflare reshuffles its dashboard now and then. If a name below doesn't match, look for the closest equivalent.

Step 1: Create a KV namespace

  1. Account level → sidebar Storage & Databases → Workers KV → Create a KV namespace.
  2. Name it plex-notices and create it.
  3. Cloudflare opens its KV Pairs page (with an Add Entry button). You don't need to add anything; the app does that.
  4. Click the Metrics tab and copy the Namespace ID from the box on the right. It goes into Settings → Cloudflare → KV namespace ID.

Step 2: Create an API token for this app

  1. Person icon (top right) → Profile → API Tokens (left sidebar) → Create Token.
  2. Under Create Custom Token, press Get started.
  3. Token name: plex-notice KV.
  4. Permissions: one row with the three drop-downs set to Account, Workers KV Storage and Edit. Nothing else.
  5. Account Resources: Include and your account.
  6. Continue to summary → Create Token. Copy the token now; Cloudflare only shows it once. It goes into Settings → Cloudflare → API token.

Your Account ID is the long string in the dashboard's address bar right after dash.cloudflare.com/.

Step 3: Create (or update) the Worker

  1. Account level → Compute → Workers & Pages → Create application.
  2. Start with the Hello World option → name it requests-fallback → Deploy → Edit code.
    Already have it? Open requests-fallback → Edit code instead.
  3. Select everything in the editor, delete it, paste the code below, then Deploy.
{{ worker_code }}

Also downloadable: requests-fallback.js. Edit FALLBACK at the top if you want different built-in text. It's only used if KV is empty or unreachable.

Step 4: Connect the Worker to KV

  1. Open the requests-fallback Worker → Settings tab → Bindings → + Add binding.
  2. Choose KV namespace → Add Binding.
  3. Variable name: NOTICES (exactly, in capitals). KV namespace: plex-notices.
  4. Add Binding.

If the binding is missing or misnamed the Worker still works, but always shows its built-in text instead of your messages.

Step 5: Optional manual switch

  1. Open the requests-fallback Worker → Settings tab → Runtime variables and secrets → + Add variable.
  2. Key: FORCE_MAINTENANCE, Value: false → Add variable and deploy.

Set it to true to show the maintenance page even while the server is up, and back to false afterwards.

Step 6: Proxy the site through Cloudflare

  1. Your domain → SSL/TLS → Overview → the blue ⚙ Configure button (top right) → choose Full (strict) and save. With Flexible, a reverse proxy that forces HTTPS causes an endless redirect loop.
  2. Your domain → DNS → Records: the site's record (e.g. requests) must have Proxy status Proxied (orange cloud). Edit it if it's grey. If the site is only covered by a * wildcard record, add an explicit one with Add record: same Type as the wildcard (A or CNAME), Name requests, Content exactly what the wildcard points to, Proxied → Save. An explicit record overrides the wildcard for that name only.

Step 7: Attach the Worker to the site

  1. Your domain → sidebar Workers Routes → Add route.
  2. Route: requests.example.com/* (your site, with /* on the end). Worker: requests-fallback.
  3. Request limit failure mode: Fail open (proceed). If you ever pass the free daily limit, visitors just go straight to your server.
  4. Save.

Use a Route, not a Custom Domain. A custom domain would make the Worker the entire site; a route puts it in front of your server. Leave the Worker's workers.dev address switched on. It's harmless, and turning it off isn't needed.

Step 8: Connect this app

  1. Settings → Cloudflare status page: tick Enable, fill in Account ID, KV namespace ID and API token.
  2. Press Test Cloudflare; it should say Connected.
  3. Check the default heading and message, then Save settings (this sends the default message to KV).
  4. In each preset, fill in the Status page heading and message you want during that kind of planned outage.

On your own network

If your local DNS (AdGuard Home, Pi-hole, your router) points the site straight at your reverse proxy, devices at home never touch Cloudflare, so they get the proxy's plain "502 Bad Gateway" instead of the maintenance page. To make home devices go through Cloudflare for this one site too, stop overriding that one name locally:

  • AdGuard Home with a wildcard rewrite (e.g. *.example.com → your server): Filters → DNS rewrites → Add DNS rewrite: domain requests.example.com, answer A (just the letter). That's AdGuard Home's way of saying "use the real public answer for this name", an exception to the wildcard. Check the docs for your version if it doesn't take.
  • A single rewrite for that name: delete it.

Check it worked: on a home device, nslookup requests.example.com should return Cloudflare addresses (often starting 104. or 172.6), not your server's LAN IP. Trade-offs: home traffic to that site now goes out via the internet and back, and it won't load at home if your internet is down.

Troubleshooting addresses

The Worker answers two special addresses on your site, even while the server is up:

  • https://requests.example.com/__plex-notice/status shows what the Worker can see: whether the KV binding works, the stored planned and default messages, and which one the page would show right now.
  • https://requests.example.com/__plex-notice/preview shows the maintenance page as visitors would see it right now, without having to stop anything.

Like the real page, these only work through Cloudflare (mobile data, or after the DNS change above).

Side effects worth knowing

  • Your reverse proxy now sees Cloudflare's IP addresses for this host instead of visitors' real IPs. Fine for a public site like a request page, but don't put an IP-based access list on it.
  • If your reverse proxy renews certificates with an HTTP challenge, check renewals still work once the site is proxied. Certificates issued by DNS challenge (e.g. wildcards) aren't affected.
  • Devices using your own DNS (LAN or VPN) may go straight to your server and skip Cloudflare entirely. That's normal, and it's why testing must be done from outside (below).

Testing the status page

Test from outside your network: a phone on mobile data with WireGuard/VPN turned off. On Wi-Fi or VPN your own DNS may route you around Cloudflare and you'll never see the Worker. Don't test with the workers.dev address either; it can only show Cloudflare's "nothing here yet" page.

  1. Normal: open your site, e.g. https://requests.example.com. It loads as usual.
  2. Unexpected outage: stop the site's container (e.g. docker stop seerr, or stop it in your Docker UI). Reload: you should see the red Server offline page with your default message.
  3. Planned outage: on the Dashboard, activate a preset that has a status message, with Also set this preset's message ticked. Wait about a minute (KV changes take up to ~60s to reach every Cloudflare location), then reload: the amber Planned maintenance page with that preset's message. If you set an auto-remove time it shows "Expected back".
  4. Clean up: remove the notice (the planned message is cleared), then start the container again (docker start seerr). Reload: the site is back.
  5. Whole house off (optional): briefly unplug the router's WAN cable and reload from mobile data. You should get the same maintenance page, maybe after up to 10 seconds while the Worker waits for your server.

Troubleshooting

"Plex didn't add the clip within …s"

The folder mounted at /notice isn't where the app told Plex to look. Compare the compose line with Settings → Plex will look for notices in: the notice folder must sit directly inside the library's folder, and its name must match (see Library in a different place). If your disks spin down, also try a longer Scan timeout.

"Can't write to the notice folder" or "Permission denied: '/data/…'"

Check the container log (docker compose logs plex-notice): the [init] lines at the top show which PUID/PGID it used and whether it could fix the folder owners. Usual causes: a user: line in compose (remove it and use PUID/PGID), or a network share that doesn't allow changing owners (root squash). In that case set the owner on the host or NAS yourself, e.g. chown -R 1000:100 /path/to/compose/plex-notice-data.

"The notice folder /notice is gone inside the container"

The notice folder was deleted on the host while the app was running, typically by Plex tidying up empty folders after deleting a notice. The app now keeps a hidden .plex-notice-keep file in it so it's never empty; leave that file there. To recover, from the folder with your compose file run docker compose up -d --force-recreate plex-notice. Docker recreates the folder and the app fixes its owner.

Notice isn't first on my TV

TV apps cache their Home screen. Back out to Home or restart the app. Also check the Dashboard's Last check line.

"Unavailable" leftover in the Movies library

Plex refused to delete an old notice, so Allow media deletion is off. Turn it on (Plex Setup above) and press Retry cleanup on the Dashboard.

Poster or title reverted

Someone ran "Refresh metadata" or "Fix match" on it. The watchdog puts title and date back within the check interval; activate again to restore everything, including the poster.

Status page shows the built-in text, not mine

Open https://your-site/__plex-notice/status from mobile data first. It says exactly what the Worker sees (see Troubleshooting addresses). Otherwise, check the Worker's KV binding is called exactly NOTICES, that Test Cloudflare passes, and that you saved settings (which sends the default). Changes can take ~60 seconds to appear.

Upload fails

"413" means NPM's upload limit (see Installing, step 5). Otherwise check the file is under MAX_UPLOAD_MB and has an accepted extension.

Something else

Look at the Activity list on the Dashboard and docker compose logs plex-notice. Each step is logged.

Security

  • Anyone who can open this app can post a notice to all your Plex users. Keep it LAN/VPN-only (NPM local-only access list), and/or turn on a password in Settings → Security.
  • The Plex token and Cloudflare token are stored in plain text in /data/settings.json. Keep the plex-notice-data folder private and out of public backups/shares.
  • The Cloudflare token only needs Workers KV Storage → Edit; it can't change DNS or anything else.
  • The container only gets write access to the _ServerNotice sub-folder, never your whole Movies library, and it only ever deletes folders it created (named notice-YYYYMMDD-HHMMSS).
  • Forgot the password? Add DISABLE_AUTH=true to the app's environment, docker compose up -d, set a new password, remove the line, and docker compose up -d again.

Updating

Replace the files in the plex-notice folder with the new version (keep plex-notice-data, which holds your settings, presets and media), then:

cd /path/to/compose
docker compose up -d --build plex-notice

If you later publish the app on GitHub with a container image (e.g. on ghcr.io), swap build: ./plex-notice for image: ghcr.io/<you>/plex-notice:latest and update with docker compose pull plex-notice && docker compose up -d plex-notice, or with your Docker UI's update button.
